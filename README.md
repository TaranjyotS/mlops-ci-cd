# MLOps CI/CD Pipeline: Data Validation, Training, Drift Monitoring and FastAPI Inference

A production-style Machine Learning Operations project that demonstrates how an ML model can move from data generation to validation, training, experiment tracking, model packaging, CI/CD checks, containerization, and online inference.

This is designed as a portfolio-ready AI/ML engineering project. It is intentionally lightweight enough to run locally, but it includes the same concepts used in real production ML platforms.

## What This Project Demonstrates

- Reproducible ML pipelines with DVC
- Data quality checks before training
- Model training with scikit-learn
- Experiment tracking with MLflow
- Model artifact and schema generation
- FastAPI inference service with typed request/response contracts
- Drift monitoring for post-deployment model health
- Dockerized deployment
- GitHub Actions for linting, security checks, tests, pipeline reproduction, and Docker builds
- Test coverage for data validation, training, drift reporting, and API inference

## Architecture

```text
Raw/Synthetic Data
      |
      v
DVC generate stage
      |
      v
Data Validation
      |
      v
Model Training + Metrics + Schema
      |
      +--> MLflow Experiment Tracking / Registry
      |
      v
FastAPI Inference Service
      |
      v
Monitoring: Drift Report
```

## Quickstart

### 1. Create and activate a virtual environment

```bash
python -m venv .venv
source .venv/bin/activate      # macOS/Linux
# .venv\Scripts\activate       # Windows PowerShell
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
pip install -e .
```

### 3. Run the ML pipeline

```bash
dvc repro
```

This creates or updates:

```text
data/raw/train.csv
reports/ge_validation.json
reports/metrics.json
reports/model_schema.json
models/model.joblib
```

### 4. Run tests

```bash
pytest
```

### 5. Start the API

```bash
uvicorn mlops_ci_cd.api.main:app --reload
```

Health check:

```bash
curl http://127.0.0.1:8000/health
```

Prediction:

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"feature1": 1.2, "feature2": 3.4}'
```

## MLflow Tracking and Model Registry

Local file-based tracking is useful for quick experiments:

```bash
export MLFLOW_TRACKING_URI=file:./mlruns
export MLFLOW_EXPERIMENT=mlops-ci-cd
dvc repro train
mlflow ui
```

For a production-style registry workflow, run an MLflow tracking server first:

```bash
mlflow server \
  --backend-store-uri sqlite:///mlflow.db \
  --default-artifact-root ./mlruns \
  --host 0.0.0.0 \
  --port 5000
```

Then configure the project and reproduce the pipeline:

```bash
export MLFLOW_TRACKING_URI=http://localhost:5000
export MLFLOW_EXPERIMENT=mlops-ci-cd
dvc repro
```

The training step logs metrics, parameters, the model schema, an input example, and an MLflow model signature so the model can be validated more safely during registry and deployment workflows.

You can also run the registry step directly:

```bash
python -m mlops_ci_cd.model.registry --name random_forest_model
```

## Drift Monitoring

After collecting new production or batch scoring data, compare it against the reference training data:

```bash
python -m mlops_ci_cd.monitoring.drift \
  --reference data/raw/train.csv \
  --current data/raw/train.csv \
  --report reports/drift_report.json
```

The drift report compares feature mean shifts and flags drift when the normalized shift crosses the threshold.
